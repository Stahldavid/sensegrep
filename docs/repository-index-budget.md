# Shared repository index admission budget

When `SENSEGREP_SHARED_OBJECTS=1` and the checkout has an explicit repository UUID binding, `withRepositoryIndexBudget(root, indexDirectory, publish)` serializes measurement and activation of a new view under a local repository guard. The default allowance is 2 GiB; `SENSEGREP_SHARED_INDEX_MAX_BYTES` selects a non-negative safe integer byte limit. Private or unregistered checkouts keep their existing behavior.

The caller stages table data first and passes an atomic **metadata-only** publication callback. The guard covers measuring and running that callback. If usage already exceeds the allowance, the callback is not invoked. The operation does not delete tables, ignore reader/clone references, or override retention pins; it reports that retained views must be released or the budget increased. Data creation must not be deferred into the callback, because admission measures the already staged state.

Accounting walks regular files beneath every `*.lance` directory in the current index (including a new index with no metadata yet) and all `project_*` indices registered to the same repository UUID. Retained generations and base tables referenced by copy-on-write views count even when they are not the active table. Immutable local repository bindings are read directly. Current hashed database directory names (including profile suffixes) and legacy default names are recognized from those bindings even when neither active metadata nor a release marker remains. Release markers also identify retained views in compatible older layouts. Removing a worktree directory or releasing its metadata therefore does not make its retained base bytes disappear from accounting. Other registered repositories do not contribute to this repository's usage.

Files are deduplicated by device and inode, so hardlinks count once. On POSIX systems the measurement uses allocated `st_blocks` in 512-byte units; Windows uses the file size exposed by Node as a fallback. This excludes directory overhead, source-object/cache storage governed by their own budgets, and native/JavaScript RAM. Filesystem compression or shared reflink extents with different inodes are not deduplicated; the measurement can conservatively overcount them. Windows file-size accounting is not an exact allocated-block bound. Symbolic links and invalid accounting metadata fail closed instead of being followed or silently ignored.

Staging and native operations occur before publication and can temporarily exceed the admission allowance. Concurrent unpublished directories in the current binding-derived layout also count, even before metadata publication. Unknown older directory layouts require metadata or a valid release marker to establish ownership; the caller's current directory always counts. Serializing publication prevents independent admission decisions over the same visible state, but it does not reserve capacity before staging. This is an activation budget, not a filesystem quota, a reservation before staging, or protection against old/nonparticipating processes writing directly. Interrupted staging may need verified cleanup.

All participants must use the same local data/state filesystem and guard protocol. An interrupted guard holder leaves a conservative guard under `repository-index-budgets-v1/<repository-id>`; stop and verify all participants before recovering it. An accounting failure never authorizes deleting uncertain referenced data.
