## Acceptance checklist

- [ ] Context and graph isolation, daemon identity and watcher ownership.
- [ ] Cross-process lock recovery, cancellation and total deadlines.
- [ ] Fixed index generation, reader retention and content identity, including transferable references.
- [ ] Real-process integration regressions across CLI, MCP and daemon.
- [ ] Resource measurements and scoped embedding reuse; decide overlay from measurements.
- [ ] Authorized immutable snapshot transport, resource limits and two-executor harness.
- [ ] Documentation, full applicable local checks and packaged artifact verification.

The index metadata, schema inspection and collection opening currently resolve the active table independently. A generation-pinning implementation must carry a single resolved generation through all consumers and protect readers against concurrent collection; merely adding a table name to metadata does not satisfy that contract. Live source validation is distinct from retaining historical source bytes. Remote transport and cross-machine compatibility must not be inferred from local processes.

## Initial implementation and validation

The first increment changes nested profile handling, graph cache identity and temporary publication, daemon handshake checks and watcher targeting, and lock queue cancellation/deadline handling. These are partial implementations, not acceptance of the phases above. In particular, daemon discovery still uses a derived port, watcher ownership has no takeover protocol, abandoned lock recovery still races, and index generation is not pinned across a read. The daemon HTTP POST endpoint now requires the instance identifier obtained from `/health`; consumers of the direct endpoint must be updated and integration-tested.

An integrated `npm run build` and `npm run check:ci` passed. With isolated XDG directories and `SENSEGREP_NETWORK_POLICY=local-only`, `npm run test:ci -- --maxWorkers=2` reported 55 passing and 6 failing files (393 passing and 48 failing tests). Many provider-mock tests explicitly expected requests that local-only denied; one MCP plugin wording assertion also failed. These failures are not a passing CI result and their complete baseline attribution has not been established. Targeted subagent runs reported 12 context/graph tests, 20 indexer tests and 5 watcher tests passing. Full packaging, cross-process, cross-runtime and remote tests remain outstanding.

Reader retention is not yet safe across processes: resolving a table name before cleanup does not protect it from a collector. A future implementation needs a cross-process acquisition protocol that closes the race between reading the active pointer, publishing a reader lease and the collector claiming the table. It must also conservatively handle crashed readers, PID reuse and inaccessible process state. Time-based retention is only an additional buffer; it is not a reader lease. Automatic cleanup has not been disabled, so callers cannot assume an old generation remains readable for an arbitrarily long-running query.

## Second increment

Endpoint discovery now uses per-instance records and ephemeral loopback ports. A startup guard elects one server among processes sharing the runtime directory. A crashed guard is retained and requires the manual procedure in the CLI README; installations using another runtime directory or the legacy derived port are not coordinated. Real-process tests cover startup contention, stale records, identity mismatch and abrupt death.

Lock owner updates are serialized with a guard. Recovery of dead owners is limited to verifiable same-boot, same-PID-namespace Linux processes; unknown owners and an abandoned guard fail closed. Legacy binaries do not respect the guard. The multiprocess test kills the owner and starts two recoverers; it does not establish recovery from death while holding the guard. To recover an abandoned guard, first stop and verify all indexers, including old versions; only then inspect and remove the corresponding `.lock.guard` directory and, for an unverifiable owner, its `.lock` file. Never remove either while an indexer may be active.

Search, literal search, graph, duplicate detection, stats and freshness verification now propagate the table selected from metadata into subsequent schema and collection reads. This does not protect the selected table from collection by another process, nor does it make live source historical. Legacy result IDs with no content hash report unknown integrity; graph expansion requires a matching live target hash and still warns that graph freshness is unverified. A table name and timestamp are not a content snapshot or a transferable repository identity.

On this increment, build, check:ci, version:check, test:node (62), release:verify, check:docs and test:python (26) passed. The full Vitest run with isolated XDG directories and a Node network guard blocking non-loopback sockets passed 450 tests and failed one outdated documentation wording assertion; the assertion was updated to check the current guidance and its two tests passed separately. Provider-mock suites previously blocked by application local-only policy passed (59 tests) under the network guard. This is local validation, not an operating-system network sandbox or a two-machine test.

During development one worker ran without isolated XDG settings and created a personal `/tmp` index lock. Its exact token and terminated PID were verified and only that created file was removed. No other personal state change was observed; this is not proof that no other filesystem metadata changed.

## Third increment and remaining limits

Superseding the earlier retention note, participating internal readers now acquire a generation lease before schema/table access, and automatic cleanup uses a serialized tombstone and checks for leases. A real LanceDB test uses a separate reader process and verifies retention until release. A dead reader or a crashed guard blocks collection conservatively. Recovery requires stopping **all** readers and writers for the index, verifying none remain, and only then removing the abandoned `reader-*` file or empty `guard` directory under that index's `.generation-leases` directory. Do not remove tombstones: they prevent a previously collected table name from being reopened. Direct public collection handles, explicit deletion and old binaries do not participate; these must not run concurrently with cleanup if protection is required. This is not a general cross-machine lease protocol.

Files newly prepared by full, incremental and watcher indexing now record a SHA-256 digest of the stable decoded source used by the parser; older metadata without it remains unknown. This digest is not a content snapshot, does not describe index coverage or immutable historical bytes, and does not authorize transfer. Invalid UTF-8 and source symlinks are rejected by this reader. The remaining compatibility contract needs explicit repository registration, a canonical manifest of the indexed universe, specification identity and retained immutable bytes.

The [local reuse microbenchmark](parallel-reuse-microbenchmark.md) measures the existing vector reuse using synthetic deterministic inputs; it does not show a real-provider speedup or justify an overlay. A persistent document embedding cache was not added: adapters transform inputs internally and the effective model revision and credential scope are not currently represented, so a safe exact-input key and cross-process coordination still need implementation. The authorized snapshot transport and common quota coordination are also not implemented.

Final integrated checks for this increment used fresh XDG directories and a Node socket guard for non-loopback hosts: build, check:ci, 457 Vitest tests, version:check, 62 Node tests, release:verify, check:docs and 26 Python tests passed. This is not a platform matrix, an OS network sandbox, a full end-to-end remote protocol test, or a test on two physical machines.

## Fourth increment

An explicit immutable repository UUID binding and canonical `indexed-files` manifest are now available. Only qualified SHA-256 hashes of the original file bytes are included; legacy hashes remain unknown. `repository register`, `status` and `manifest` expose the binding and manifest without rebuilding. A source bundle can be captured only while the indexed generation exists and every live file matches the manifest. The local-only snapshot service exposes one explicitly selected bundle behind a token, and `snapshot fetch` validates identity and every file before storing in a private destination. `snapshot reference` and `snapshot show` create and resolve explicit portable source locations. These locations prove the selected bytes and line range; they do not establish a graph symbol or search ranking. The normal live `show` refuses portable IDs rather than silently accepting them. See the CLI README for the authorized encrypted-tunnel recipe. The bundle contains sources, not LanceDB, and no index is activated or index-spec compatibility asserted.

The opt-in document cache and local shared quota have separate instructions in [document-embedding-cache.md](document-embedding-cache.md) and [shared-provider-quota.md](shared-provider-quota.md). Bedrock caching is disabled because its effective endpoint can be selected by the AWS SDK. The quota is an estimate coordinated by cooperating local processes, not a strict provider limit or a cross-machine coordinator. [A synthetic benchmark](document-cache-microbenchmark.md) shows fewer simulated inputs but higher latency than its inexpensive mock; it does not establish real-provider savings. Linux leases for definitely dead readers in the same boot and PID namespace can now be recovered automatically; unknown owners and abandoned guards still require conservative manual recovery.

The integrated build, check:ci, 481 Vitest tests, version:check, 62 Node tests, release:verify, docs link check and 26 Python tests passed with isolated XDG directories and the local Node socket guard. Remaining plan work includes complete index-spec identity, automatic guards recovery on supported platforms, index artifact transfer/activation with verified spec and permissions, shared quota across machines, full CLI/MCP/daemon identity parity, and real two-machine validation. Current source-bundle transfer does not claim those properties.

A subsequent smoke test ran the built CLI and built core with a real LanceDB generation containing a deterministic vector: registered repository and manifest, `snapshot serve`, `fetch`, `reference`, and `show` succeeded between two isolated XDG environments on the same host; an incorrect token was rejected. It did not call a provider or validate two physical machines. Temporary data and server were removed after the test.

Index metadata now additionally records a partial specification observation. It exposes the provider, model, dimensions and chunking/tokenizer fields present in metadata, while marking parser/fallback, model revision and transformation as unknown. This observation is not a compatibility proof; a complete index-spec hash is deliberately not emitted. Legacy metadata remains readable.

A packed-artifact smoke test recreated core and CLI tarballs offline with `npm pack --ignore-scripts --offline`, extracted them into a temporary environment with local dependencies, and ran the packaged CLI and core against a real deterministic LanceDB generation. `--help`, source bundle serve/fetch/reference/show and rejection of an incorrect token passed using two isolated XDG environments on one host. No publication or provider call occurred; the temporary environment and server were removed.

## Architecture correction

The current target is defined in [parallel-agent-architecture.md](parallel-agent-architecture.md); this chronological log contains superseded observations. The audit identified disconnected identity contracts, discarded identity fields in projected output, and dependence on the live checkout when exporting historical source.

Queries now report distinct generation, content and recipe identities, and projections preserve them across CLI/MCP/daemon envelopes. Legacy snapshot aliases remain explicitly scoped. A canonical recorded recipe hash is emitted with scope `recorded-recipe-v1`; incomplete reproduction information stays explicit and the hash alone does not authorize vector reuse. New source objects are atomically stored before metadata publication in full, incremental and watcher indexing, and capture uses these verified historical bytes before considering legacy live fallback. Original objects survive generation cleanup, with storage growth and manual retention policy documented in [source-object-store.md](source-object-store.md).

Additional defects corrected by the audit include literal searches under indexed parents, content validation before attaching indexed symbols, live/indexed graph mixing, cancellation and embedding configuration parity in grouped searches, daemon profile resolution and diagnostics for a startup guard. The corrected graph cache version invalidates old persisted results that could have used divergent live bytes.

Validation after integration: build and workspace types passed; 496 Vitest tests, 62 Node tests and 26 Python tests passed; version checks, package artifact verification and links for affected documentation passed. All XDG directories were isolated. No remote provider, production system or physical second machine was used. Ordinary search cards still use legacy local IDs; explicit portable IDs are created through the snapshot reference operation. Complete vector import and distributed quota remain separate extensions, rather than prerequisites for the safe immutable-source handoff.

The final offline packed-artifact smoke returned exit code 0: a real deterministic LanceDB generation and original source object were prepared, the live file was changed, and the packaged `serve → fetch → reference → show` flow returned the original historical BOM/CRLF bytes. Two complete isolated XDG environments were used on one host. Temporary data and processes were cleaned; reproducible local evidence was retained in `/tmp/sensegrep-historical-packed-smoke.mjs` and `/tmp/sensegrep-historical-packed-smoke.log` (temporary paths, not permanent repository fixtures).

## Shared physical worktree views

The clarified target is implemented as native LanceDB copy-on-write tables, not a hand-written overlay ranking engine. Explicit repository registration plus `SENSEGREP_SHARED_OBJECTS=1` enables compatible cold bootstrap, shared source objects and the optional embedding cache. Each worktree/profile has independent metadata and its own table manifest; additions/deletions/renames remain private. Cold initialization coordinates once per repository/profile, and actual runtime-artifact identity is required before using another checkout as a seed. Missing plugin/runtime identities disable this optimization. Full-copy checkpoints bound dependency depth; generation and byte admission budgets retain readers and dependencies rather than evicting them to fit.

Source generation references and publication pins now drive collection. `repository release` and `gc` release logical views and reclaim physical data after readers/dependencies end, including paths of removed checkouts. The extension's delete path uses the same exclusion. Watchers honor the release marker under the root mutation lock. A process shares one bounded native Lance session and bounded connection/table maps; these are cache limits rather than a total RSS guarantee. Shared repository storage accounting includes bases retained without active metadata and profiles whose checkout roots have been deleted.

Snapshot protocol v2 negotiates a manifest and fetches missing objects. Valid objects received before an interruption are persisted for retry. Replica stores contain one object per digest and small manifests with count/byte retention; explicit pins survive GC. CLI exposes replica pin/unpin/gc. Legacy embedded snapshots and v1 servers remain readable; no mixed-directory rewrite is inferred. Each executor owns its local mutable Lance state. Cross-executor source replication does not transfer native Lance fragments or provider credentials and requires no new user-account service.

The measured COW implementation, setup, lifecycle and detailed limits are in [shared-worktree-indexes.md](shared-worktree-indexes.md), [COW benchmark](cow-view-benchmark.md), [runtime identity](indexing-runtime-identity.md), [repository admission](repository-index-budget.md) and [replica retention](replica-source-store.md). The new `.changeset/shared-worktree-views.md` records the candidate changes; no package was published or globally installed.

All temporary directories/processes were cleaned. These tests used one physical host and a deterministic loopback provider, not a paid provider or two physical machines.
