# Local indexing implementation identity

`getIndexingRuntimeIdentity()` in `semantic/indexing-runtime-identity.ts` returns a SHA-256 identity for the resolvable local indexing artifacts, or `undefined` when their identity cannot be established. It does not call a provider or download files.

For the supported unbundled layouts, it hashes all runtime modules under the core `src` (`.ts`) or `dist` (`.js`) directory, excluding tests, declarations and source maps; the core package manifest; the installed web-tree-sitter JavaScript runtime and WASM; the installed TypeScript, TSX, JavaScript, Python, Java and Vue grammar WASMs; and both installed tokenizer JavaScript entrypoint variants. Relative labels, byte lengths and file hashes are sorted and combined with the representation, Node version and builtin registry IDs. Absolute checkout paths are not hashed. Two independent checkouts using identical local artifacts can therefore agree, while a code/grammar/tokenizer change invalidates reuse. Hashing all core runtime modules is deliberately conservative: even a change outside the chunker can invalidate the identity.

Source and compiled distribution are distinct representations and intentionally receive different identities. Esbuild bundles that lose the resolvable `src/semantic` or `dist/semantic` layout return `undefined`, rather than pretending that adjacent files describe their executable implementation. Missing, oversized or changing files also fail closed.

The function checks the active language registry against snapshots of the builtin descriptors, methods, extension ownership and reserved-word sets. Configured plugins, additional languages or replacements make the identity unknown. Arbitrary external plugin closures are not identified from their names or `Function.toString()`. Call it after loading the languages/plugins selected for the indexing operation.

The identity covers the stated local artifacts; it is not a complete transitive supply-chain attestation, a provider's effective model revision, an account/endpoint authorization, proof of deterministic output, or protection against monkey-patching by arbitrary code in the process. Runtime artifacts must remain immutable while a process uses them. Model revision/configuration compatibility, source snapshot identity and permission to share a repository remain separate requirements.

Five tests cover a valid deterministic source layout; changed chunking bytes without altering checkout files; missing grammar; configured/dynamically registered plugins; and a real esbuild child process with an unresolved bundled layout. Every test command uses isolated XDG config, cache, data and state paths. A compiled-distribution smoke subsequently passed: two Node 24.16.0 processes using different empty checkout directories and complete isolated XDG environments loaded `packages/core/dist/semantic/indexing-runtime-identity.js` and produced the same nonempty identity. The observed build identity was `sha256:7129c8f467da0d1b7fca3c0e82b9382ead563382cb5d396ac12f3428d84ff26a`. The test imported the built language registry before the identity API, made no provider calls, removed its checkout data, and retained its temporary script/log under `/tmp/sensegrep-dist-runtime-identity-smoke.mjs` and `.log`. This verifies the built distribution, not source/distribution identity equality.
