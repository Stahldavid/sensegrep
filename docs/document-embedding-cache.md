# Opt-in document embedding cache

Document caching is disabled unless **both** `SENSEGREP_DOCUMENT_CACHE_REVISION` and `SENSEGREP_DOCUMENT_CACHE_ACCOUNT` are set to nonempty values. Set the revision to a stable identifier for the exact model revision deployed by the provider. Set the account value to an opaque, non-secret identifier for the provider account or deployment. Change either whenever its meaning changes. Sensegrep cannot verify that a provider keeps a mutable model alias or endpoint stable; a revision supplied incorrectly can return an old vector. Never place an API key or token in either variable.

The cache is currently used only for `RETRIEVAL_DOCUMENT` with the OpenAI-compatible and Gemini adapters. It is bypassed for benchmark operations, query embeddings, Bedrock and Ollama. By default it is scoped by canonical checkout directory and profile. With `SENSEGREP_SHARED_OBJECTS=1`, checkouts explicitly registered to the same repository UUID share a physical cache for the same profile. Unregistered checkouts keep their private cache. Different repository UUIDs, profiles, account scopes, revisions and effective input/configuration identities remain separated. Keys include the post-validation text sent to the adapter, Gemini document title where sent, provider, endpoint, model, requested dimension, task type, adapter transformation version, declared revision and account scope. Cache files contain vectors and metadata, not source text or credentials. Keys are hashes, which are not encryption and can reveal guesses about known inputs; protect the user's cache directory accordingly.

A local directory guard serializes cache reads, provider misses and atomic publication across participating processes, preventing duplicate requests for the same missing input. If a process dies while holding the guard, subsequent access fails after a bounded wait. Stop and verify all users of that checkout and profile before removing the abandoned `.guard` directory under the corresponding `document-embeddings-v1` cache directory. Do not remove it while a process may hold it. Older binaries and caches outside this implementation do not participate. Invalid or incomplete entries are treated as misses; finite vectors of the expected dimension are required. The cache retains at most 2,000 completed entries per storage scope/profile, evicting by publication time; temporary files from a killed process may need manual cleanup after verification.

This cache does not infer repository identity, coordinate a provider quota across machines, or prove a real provider's model revision. Repository registration and shared-object opt-in are required before worktrees share cached vectors. It should be evaluated with representative workloads and explicit cost/latency measurements before drawing performance conclusions.
