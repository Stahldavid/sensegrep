# Shared source retention

This protocol is for cooperating processes on one local filesystem. Source sharing is explicitly enabled by repository scope; sharing an identity does not automatically authorize another repository. Shared immutable objects have one shared filename and local per-index hardlinks. Each local hardlink is a durable filesystem reference, so collection never removes the only shared name of an object still linked by a checkout.

`withSourceRetentionPin(indexDirectory, fn)` protects the entire source publication or multi-object read operation. Generation reference manifests are written before activating index metadata. They record the qualified raw source hashes for that generation; generation identities are immutable. References are removed only after dropping the corresponding generation under its reader leases. Explicit retained snapshots can use additional references and must be released explicitly. A crashed publication pin fails closed and blocks local collection until all index users have stopped and an operator has verified that its unique pin is abandoned.

`collectSourceObjects` requires the complete list of retained physical generations. A missing legacy reference, incomplete hash identity or active publication pin causes collection to skip. The collector keeps the union of every generation/snapshot reference and removes only unreferenced local object names. Its default unreferenced byte allowance is zero; callers can retain an unreferenced cache by supplying `maxUnreferencedBytes` and `maxAgeMs`. Removing a local name does not remove another checkout's hardlink. Call collection after releasing publication pins, or it deliberately skips.

Shared publication, local linking and shared eviction use the same directory guard. `admitSharedSource` evicts shared entries only when their link count is one, meaning no participating local index references them. `SENSEGREP_SHARED_SOURCE_MAX_BYTES` limits completed unique objects per repository scope (default 512 MiB); `SENSEGREP_SHARED_SOURCE_MAX_AGE_MS` expires unreferenced cache entries (default seven days). If active references prevent the requested admission from fitting, it reports capacity rather than evicting referenced data. Recognized interrupted temporary names are removed under the publication guard. Atomic publication can temporarily require additional space up to one incoming object; these limits do not account for unrelated files or filesystem metadata.

A shared guard left by a killed writer is not removed automatically. Stop and verify every cooperating user before inspecting and removing that directory. Other filesystems, old binaries that ignore the guard, manual file manipulation and cross-machine sharing of a mutable directory are outside the protocol. Cross-filesystem hardlink fallback can create a separate local copy; the shared object's budget is not a total-machine disk quota. This implementation does not guess reachability from branch names or timestamps and never evicts current view references to force an arbitrary budget.
